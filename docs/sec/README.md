# SEC(第2弾以降)とプロモーションカードの方針

第1弾の SEC は額縁+ギョーシェ柄。第2弾以降の SEC とプロモーションカードは、1枚ごとに専用デザインにする。
2026-10-11 に作者と相談して決めた方針。

## 決まっていること

1. **共通の「署名」は番号・レア印・裏面だけ**。右下に番号と金のレア印(`src/cards/special/Signature.svelte`)、裏面は全カード共通の `CardBack`。それ以外(文字組・色・動き・加工)は自由。
2. **写真は切り抜かない**(2026-10-11 改定)。写真 1 枚でそのまま成立し、**デザインの哲学が車両とその写真に合っている**ものにする(例: PR-02 は 2005 年のショー会場の写真に、フィルム調+最小限の文字)。色調整・粒子・トリミングは可、すべて CSS。改変した写真は「改変あり」としてクレジットする。PR-01 は改定前の作品なので切り抜きを使っている。
7. **写真選びは道具で確かめる**: 候補は `scripts/photo-check.py` で「車の顔(フロント)が写っているか」を判定してから選ぶ。縮小した一覧だけで決めない(下の「写真の選び方」)。
3. **登場演出**: 入口は全 SEC 共通(暗転 → 金の縁 → めくる)。めくった直後に、そのカード固有の動きを 1 回だけ再生する。
4. **枠は使わない**。カードは**縦(63:88)でも横(88:63)でもよい**(横は `landscape` に id を登録)。
5. **アニメーションを付けてよい**(常時のゆっくりした動き+登場時の `moment`)。`prefers-reduced-motion` では止める。
6. **書体**: 参考にした作品と似た雰囲気の書体を、Google Fonts / GitHub の無料書体(SIL OFL など)から選び、@fontsource で同梱する。アプリ内蔵の書体(Barlow 等)は、それが最適なときだけ使う。有料書体は使わない。

## 制作プロセス

| 段階 | やること | 残すもの |
|---|---|---|
| 1. 車種 | なぜこの車か、を一文で | `docs/sec/<id>.md` の冒頭 |
| 2. リサーチ | アワード系ギャラリー(CSS Design Awards は内蔵ブラウザで閲覧可。Awwwards / CodePen は制限あり)を見て、雰囲気が合う作品は**ジャンルを問わず**拾い、良いものは**実サイトにも訪問**する。メモするのは**手法だけ**(構図や見た目は写さない) | 手法の表 |
| 3. コンセプト | 一文+キーワード 3 つ | 同上 |
| 4. 写真 | コモンズからコンセプトに合う構図を選ぶ。ライセンス確認(CC0 / PD / CC BY / CC BY-SA) | ファイル名・作者・ライセンス |
| 5. ラフ | 文字だけの配置図で作者と合意 | 配置図 |
| 6. 実装 | `src/cards/special/<Id>.svelte`、`specials` に登録。切り抜きは rembg(u2net)で作り `public/promo/` か `public/sec/` へ | コンポーネント |
| 7. 確認 | 読みやすさ、重さ(画像 300KB 以下目安)、めくる前のネタバレ、クレジット、`prefers-reduced-motion` | 確認結果 |
| 8. 記録 | 判断と、次に活かすことを記録 | このフォルダ |

## 部品

- `src/cards/special/index.ts` — id → コンポーネントの対応表。カードは `{ promo, interactive, flipped, tilt, wink, firstPulledAt }` を受け取る。
- 傾きの値は `--pointer-from-left` / `--pointer-from-top`(0〜1、単位なし)を使う。`--rotate-*` を deg で割る計算は Safari で効かない。
